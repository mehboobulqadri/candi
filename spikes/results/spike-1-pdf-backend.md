Methodology: `open_ms` = open + page_count, timed from before the file read (cross-backend comparable — poppler's read is included, matching mupdf/pdfium); `extract_ms` = full-doc extraction, string fully built before printing, best of 2 runs; chars/s from the same run; `baseline RSS` = VmRSS at process start (before open); `process peak` = /proc/self/status VmHWM after both runs (VmHWM is a process-wide monotonic high-water mark, so one value per process, not per run); `delta vs baseline` = peak − baseline. Sample = first text page, first 300 chars (extendable via `SAMPLE_PAGE`/`SAMPLE_LEN`).

## Error paths (exact messages)

| Case | mupdf | pdfium | poppler |
|---|---|---|---|
| missing file | `not found: cannot open /tmp/does-not-exist.pdf: No such file or directory` | `not found: No such file or directory (os error 2)` | `not found: No such file or directory (os error 2)` |
| malformed (truncated 1000-byte PDF) | **silent**: opens as 0-page doc; extraction says `no text layer`, sample says `MuPDF error, code: 4, message: invalid page number: 1` | `malformed: FPDF_ERR_FORMAT` at open | `PDF document is damaged` at open |
| encrypted, no password | `encrypted: document requires a password and none (or a wrong one) was supplied` | `encrypted: FPDF_ERR_PASSWORD` | `Document is encrypted` |
| encrypted, wrong password | same message as above | `encrypted: FPDF_ERR_PASSWORD` | `Document is encrypted` (identical — poppler-glib doesn't distinguish) |
| image-only PDF (synthetic) | `no text layer (extraction produced 0 chars)`, no crash | same | same |

Finding: mupdf is the weakest on malformed-input detection — a truncated file opens "successfully" and the error only surfaces as a confusing `invalid page number` on page access. pdfium and poppler reject at open. Wrong-password-vs-no-password is distinguishable in mupdf (authenticate() returns false) but not via poppler-glib error strings. Every case above exits 1 (probe now returns nonzero on any error path), while all real-doc runs exit 0 — run.sh distinguishes failure from success and aborts loudly on unexpected failures.

## Build pain / integration

| Backend | Build | Runtime deps | License |
|---|---|---|---|
| mupdf | vendored C build in crate (~5–10 min first time, no network, needs make/gcc); crate size 65 MB in cargo cache | none | AGPL-3.0 (acceptable per user decision; commercial license also available from Artifex) |
| pdfium | crate is pure bindings (fast); libpdfium.so must be supplied (prebuilt download, 7.6 MB) | one shared lib at runtime (dlopen, no link-time dep) | libpdfium BSD-3-Clause; Rust wrapper MIT OR Apache-2.0 |
| poppler | poppler-rs 0.26 glib bindings; needs system libpoppler (26.07.0 present here) + glib/cairo dev files | libpoppler-glib | GPL-2.0 |

## Pass/fail vs docs/spikes.md

- License check (done first, per recommended order): MuPDF AGPL-3.0 — user ruled acceptable, not disqualifying. PDFium BSD-3-Clause. Poppler GPL-2.0. All three licensable for this project; only MuPDF's AGPL imposes copyleft on Candi + Python bindings (accepted).
- Prototype on novel + two-column paper + large scanned-with-text-layer: done (frankl, attention, alice-scan + 3 more docs).
- Two-column reading order without manual reordering: **PASS for all three** (page 2 column-major order verified).
- Rust binding maturity: mupdf 0.8.0 and pdfium-render 0.8.37 are both usable and safe; poppler-rs is glib-idiomatic and usable but has no structured-text API.

## Recommendation

1. **MuPDF — winner.** Fastest extraction (up to 5.2M chars/s, small-doc open 1–5 ms), highest text fidelity (most chars, clean glyphs, paragraph breaks), the only backend with a true structured text API (blocks/lines/words — exactly what the production `candi-pdf` trait needs), self-contained vendored build, and the AGPL license is already accepted. Weaknesses: malformed files are detected late (needs an explicit page-count>0 or open-time sanity check in production), process peak 294 MB on the 889-page book.
2. **PDFium — runner-up.** Best license story (BSD), lowest process peak (90 MB), correct two-column order, fast enough (0.7–3.3M chars/s) though ~2–4x slower than mupdf on small docs and slower per-char on dense books; the Rust crate needs a prebuilt libpdfium.so delivered alongside (acceptable, 7.6 MB); positional data is only an approximation (object/segment counts).
3. **Poppler — third.** GPL-2.0 (same copyleft burden as AGPL but with a weaker license for the rest of the stack), slowest extraction on large docs (0.61M chars/s), highest baseline RSS (15 MB glib), no structured text API in the glib bindings, and it drops the most characters on dense/scanned books.

Fallback posture: if MuPDF's AGPL ever becomes a blocker, PDFium is a drop-in-quality replacement for text extraction (identical reading order on the two-column test), so the backend trait design in `main-probe/src/lib.rs` is validated for either choice.

## Failed/hung commands and root causes

- Previous attempt's hang: `pdfium-auto` with `bundled` feature — its build.rs downloads pdfium C++ source and compiles it at build time (multi-hundred-MB fetch + long build). Root cause: wrong pdfium strategy; replaced with dlopen of a 7.6 MB prebuilt `libpdfium.so` (downloaded once, `curl --fail --max-time 90`). No hang this attempt.
- No command hung or timed out during this run; every build/run was wrapped in `timeout` and completed within budget (longest: mupdf vendored C build in the initial debug compile, ~5 min).
- One command failure (non-hang): `convert` (IMv7 deprecation warning + wrong filename — pdftoppm outputs zero-padded `imgonly-001.png`); resolved with `magick`.
- Two measurement bugs found during the drill and fixed: (1) `sample_text` truncated to 300 chars inside the backends, so `SAMPLE_LEN` had no effect — moved truncation to the probe; (2) pdfium probe run without `PDFIUM_LIB` set failed with `LoadLibraryError` — env var is required by design; run.sh always sets it.
- Review-fix pass (2026-08-20, independent merciless review verdict "fix-then-pass"): `positions_stats` now propagates real page-load errors as `Err` (was `.ok()?` swallowing them); per-run `peakRSS` label removed in favor of one honest `process_peak_mb` + `delta_vs_baseline_mb` per process; poppler `open_ms` now includes the file read; `u16::try_from` guards pdfium page indices; probes exit nonzero on error paths; run.sh generates its error fixtures, is `set -euo pipefail` + ERR-trapped, and asserts exactly one corpus match per book. Metrics table above is from this fixed probe.
